# editor-shortcuts-and-pitfalls

> 保存时间: 2026-09-21（人工整理，非工具写入）

> 摘要: 常用快捷键、为什么"命令好像只能在地图场景用"、Lua 的适用范围、AI 助手能力边界、以及改这个项目的习惯。

---

## 常用快捷键

| 键 | 作用 |
|---|---|
| `F3` | 调试控制台（**全局**：任何场景都能开/关，含开始界面；长按不重复触发） |
| `F2` | 地图截图（交互式：先选模式，再选保存路径，带进度条） |
| `N` | 视图标签循环：隐藏 → 格子序号 → 坐标 |
| `B` | 六角网格线开关 |
| `F1` | 第二层地形显示开关；`Ctrl+F1` 帮助文本 |
| `Esc` | 从编辑模式返回主场景 |
| `Ctrl+S` / `Ctrl+Z` / `Ctrl+Y` | 快速保存 / 撤销 / 重做 |

## 为什么"命令好像只能在地图场景用"

几乎所有业务命令都包在 `WithModifiers(...)` 里：**拿不到 `MapData` 就打印"地图数据未加载"并直接返回**。
所以在军团 / 国家 / 建筑 / 将领等**没有地图的编辑场景**里，能用的只剩少数不碰地图的命令：

- `screenshotscene`（截整个界面，不要求地图）
- `screenshot --scene`（同上）
- `help` 之类

要做地图操作 → 先切回渲染场景（地图场景）再执行。

## Lua 的适用范围

- `lua <脚本.lua>` 命令**由渲染场景注册**，且第一句就要求已加载地图 → **非地图场景里没有 Lua**；
- AI 的 `run_lua` / `run_lua_file` 在非地图场景同样是空实现（`BeginScene` 把 `LuaCodeRunner` 设为 `null`）；
- 脚本整批可撤销（`Ctrl+Z` 一次退回），所以批量改图的脚本比较安全；
- Lua 里**没有**经纬度接口 —— 需要经纬度换算的脚本要自带投影（参考 `scripts/mapgen/build-map.lua`）。

## AI 助手的能力边界

- `open_scene` 只能切 `BeginScene` 列表里的编辑场景；渲染场景（战役/征服/战术地图）需要走"加载地图文件"流程，不开放给 AI 直接切；
- 截图入口由**主窗口**注册（分发器 `EditModeManager.CaptureScreenshot` 按 `SceneMode` 选实现）→ `capture_screenshot mode=scene` 到处都能用，而 `mode=full/region` 只在渲染场景有意义；
- 工具结果里的 `[OK]` / `[FAIL]` 表示执行成败；模型还应遵守系统提示里的"记忆准则"（新会话先 `list_memories`）。

## 改这个项目的习惯

- **动手前先 `read_file` 看当前内容**，再定点替换；`RenderSceneBase.cs` / `MainWindow.xaml.cs` / `CliCommandHost.cs` 这类大文件**绝不要整体重写**；
- 编辑器开着时 `dotnet build` 主项目会因 dll 被占用失败 → 只 build 改动的子项目即可验证语法；
- 向用户汇报时说清"哪些是环境限制（如无 GUI 时截图不可用）、哪些是真正改了行为"，不要把"编译通过"说成"功能已验证"；
- 修 bug 时先定位"哪一层没接上"（Core 回调没注册？命令没注册？场景没绑键？），再改 —— 本项目大量问题都是"能力存在但没接上"。
