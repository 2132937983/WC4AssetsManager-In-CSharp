## 一、这是什么

`.zme` 就是**纯文本的命令清单**：一行一条 [CLI 命令](cli-commands.md)，从上到下逐条执行。

```
# 例：给三个城市设归属
belong set 108 23 0    # 哈尔滨
belong set 103 19 0    # 齐齐哈尔
belong set 109 21 0    # 绥化
```

它**不是**编程语言：没有变量、没有条件、没有循环。适合"固定流程的批量操作"。
需要判断/计算/遍历时用 [Lua 脚本](lua-scripting.md)。

## 二、文件格式

| 规则 | 说明 |
|---|---|
| 编码 | **UTF-8**。含中文名称时必须是 UTF-8，否则城市名会乱码 |
| 换行 | CRLF / LF 都行 |
| 一行一条命令 | 命令与选项的写法同控制台，见 [CLI 指令手册](cli-commands.md) |
| 空行 | 忽略 |
| 注释 | 整行注释：行首是 `#`、`;`、`//`；**行尾注释**：这三个符号前是空白时截断到行尾 |
| 缩进 | 无所谓，前后的空白都会去掉 |
| 路径含空格 | 用英文双引号包起来：`run "D:\my maps\a.zme"` |

行尾注释是 `.zme` 最实用的地方 —— 每条命令后面写上"这条在干什么"，几百行也能看懂：

```
belong set 23 23 47     # 圣彼得堡 → 莫斯科维恩专员辖区（索引47）
belong set 89 71 27     # 伊尔库茨克 → 布里亚特（代，原势力无军团）
```

> 注：`#` 只有在**前面是空白或行首**时才当注释，所以 `run "a#b.zme"` 里的 `#` 不会被误伤。

## 三、怎么运行

**方式 A — 拖放**：把 `.zme` 文件直接拖到控制台窗口上。

```
[脚本] 加载脚本文件: tno-russia-belong.zme
[脚本] 进度: 200/742
[脚本] 进度: 400/742
...
[脚本] 执行完成: 720 条命令, 22 条注释跳过, 共 742 行
```

**方式 B — 命令**：

```
run "Maps/背景图/tno-russia-belong.zme"
```

相对路径基于**程序所在目录**（不是当前目录、也不是你上次打开文件的地方）。

拖放得到的是**绝对路径**，不受这个限制，含空格的目录也能用。

## 四、能用哪些命令

| 运行方式 | 可用命令 |
|---|---|
| **拖放 `.zme`** | CLI 命令树 + 控制台本地命令（`help`/`clear`/`echo`/`log`…）+ 场景层命令（`undo`/`redo`/`lua`/`goto`/`geo_*`…） |
| **`run xxx.zme`** | **只有 CLI 命令树**（`terrain`/`province`/`building`/`belong`/`legion`/`army`/`trap`/`info`/`check`/`fix`/`run`） |

也就是说：脚本里要用 `undo`、`lua`、`goto` 这类命令，得**拖放**运行，或者把命令换成 CLI 树里的等价形式。

## 五、执行语义（重要）

### 5.1 顺序执行，逐条生效

上一条的效果会立刻影响下一条。例如先 `belong clear` 再逐城 `belong set`，和反过来写是两种结果。

### 5.2 批量模式：不记撤销

脚本执行期间处于**批量模式**，**不记录撤销**（几百上千条命令每条都存一份全图快照会撑爆撤销栈）。

- ✅ 跑得快
- ❌ 跑错了 `Ctrl+Z` **撤不回来**

**跑脚本前先存盘**，或者对写文件的命令（`fix`）留意它自动生成的 `.bak`。

### 5.3 单条失败不会中断脚本

某一行命令报错（参数写错、坐标越界、`belong set` 落在裁剪区外…），控制台会打印错误，但**脚本会继续往下跑**。

所以脚本跑完**务必看摘要**：

```
[脚本] 执行完成: 720 条命令, 22 条注释跳过, 共 742 行
```

以及控制台里有没有夹着失败行。想"出错就停"，用 Lua 脚本自己判断 `r.Success`。

### 5.4 只在结尾/分批汇报

跑的过程中不会实时刷新界面（每 200 条打一次进度）。几百行的脚本基本是瞬间跑完。

## 六、用 `--out` 留档

任意命令加 `--out` 可以把该次输出另存成日志文件（控制台照常显示）：

```
legion list --out                      → Logs\时间戳_legion.log
belong stats --out D:\belong-report.txt
building list -n --out=city-list.txt
```

脚本动辄几百行、控制台会被刷走，`--out` 比翻屏可靠得多。详见
[CLI 指令手册 · 全局输出重定向](cli-commands.md#四全局输出重定向---out)。

## 七、示例模板

### 7.1 批量删建筑

```
# 先看一遍再删
building list -n --out

# 删除所有非首都建筑
building remove-non-capital

# 存盘检查
info --out
```

### 7.2 批量设归属

```
# 清空旧归属（可选）
belong clear

# 逐城设归属；第三个数是【军团索引】，先跑 legion list 看索引表
belong set 23 23 47     # 圣彼得堡
belong set 21 35 47     # 莫斯科
belong set 8  34 45     # 基辅

# 复查：会把每个值解析成势力名
belong stats --out
```

> ⚠️ 归属值填的是**军团索引**；填国家ID只有在"国家ID ≥ 军团总数"时才生效。
> 详见 [CLI 指令手册 · 归属值存的是军团索引](cli-commands.md#81-归属值存的是军团索引不是国家id)。

### 7.3 批量改地形

```
terrain set-edit-layer 1
terrain greening -p 60
terrain create-coast
terrain process-ocean-layer2
terrain export-hd
```

### 7.4 按区域刷归属

```
# 矩形区域整片刷成归属 3
belong set-region 80 40 100 60 3

# 按省区刷（省会所在格定位整片省区）
belong set-province 89 36 1
```

### 7.5 生成 + 整理单位

```
army remove-all
army generate-by-prob -1 60
army batch-plan-by-legion 3 1
army auto-general 3 5
army list --out
```

## 八、程序化生成 .zme

`.zme` 是纯文本，很适合**由程序生成**（比如从地图数据、表格、OCR 结果、其它脚本的输出导出）：
按坐标排序、每条带行尾注释、前面留一段说明头 —— 几百上千行也便于人工核对与局部修改。

一个生成脚本的推荐结构：

```
# 说明头：脚本用途、数据来源、生成时间、注意事项
#        需要先做的前置操作（比如"先跑 legion list 拿索引"）也写在这里
#
# ── 第一段：能确定的部分 ──
belong set ...
# ── 第二段：推测/待定部分（整段可删）──
belong set ...   # (推断)
```

**两个建议**：

1. **注释里写下依据**（势力名、原值、为什么这么填）。日后要改，看注释比重跑一遍快。
2. **把"能确定的"和"拿不准的"分成两段**，拿不准的整段可删/可替换，不用逐行找。

### 幂等性

`.zme` 本身不保证幂等：`building add` 会重复添加，`belong set` 重复设同一个值则没事。
要重复跑，优先用**赋值语义**的命令（`set` / `set-region` / `set-province`），少用**追加语义**的（`add`、`generate-by-prob`）。

## 九、常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 中文城市名乱码 | 文件不是 UTF-8 保存的 |
| `找不到脚本文件` | `run` 的相对路径基于**程序目录**；改用绝对路径或拖放 |
| 路径含空格报"无法识别" | 加引号：`run "D:\my maps\a.zme"` |
| 某个 `building add` 没生效 | 该格已有建筑（`add` 不会覆盖），先 `building remove x y` |
| `belong set` 整片失败 | 落在征服地图的裁剪区外，或该地图没有归属数据。见 [CLI 手册 8.4](cli-commands.md#84-归属覆盖范围受地图裁剪区限制) |
| 颜色和预期对不上 | 归属值填成了国家ID，被当成索引解析了。跑 `legion list` 核对第一列 |
| 跑完 `Ctrl+Z` 撤不回来 | 批量模式不记撤销（见 5.2），跑前先存盘 |
| 脚本中途报错但后面照跑 | 单条失败不中断（见 5.3），看摘要与控制台的失败行 |
| 拖放能用 `undo`，`run` 里不能用 | `run` 只走 CLI 命令树（见第四节） |

## 十、和 Lua 脚本怎么选

| | `.zme` | `.lua` |
|---|---|---|
| 本质 | 命令清单，逐行执行 | 真正的编程语言（MoonSharp） |
| 能力 | 只用已有命令 | 循环 / 条件 / 计算 / 函数 / 遍历地图数据 |
| 适合 | 固定流程的批量操作、**由程序生成的清单** | 带逻辑、要读数据再决定改什么的处理 |
| 出错 | 继续往下跑 | 中断并报错位置 `(行,列)` |
| 撤销 | **不记**（批量模式） | 整次执行包成**一个**撤销单元 |
| 入口 | 拖放 / `run xxx.zme` | 拖放 / `lua xxx.lua` |

两者会互相调用：Lua 里可以发 CLI 命令，`.zme` 里也能用 `lua`（拖放运行时）。
但**能用 `.zme` 表达清楚的，就用 `.zme`** —— 它透明、可 diff、可让程序生成、出错一眼看得出是哪一行。
